# YourTube

Мини-клон YouTube на FastAPI, PostgreSQL и JavaScript. FFmpeg преобразует загруженное видео в MP4 (H.264/AAC) и создаёт обложку. Плеер поддерживает перемотку через HTTP Range.

## Запуск на Ubuntu

Из каталога с исходниками выполните одну команду:

```bash
bash deploy.sh
```

Нужны Ubuntu с systemd, доступ в интернет и права sudo. Скрипт при необходимости установит Docker Engine, Buildx и Compose из официального APT-репозитория Docker, затем соберёт приложение и дождётся готовности обоих контейнеров. Повторный запуск обновляет приложение и использует существующие тома и пароль из `.env`.

- Интерфейс — http://localhost:8000/
- Swagger — http://localhost:8000/docs
- `sudo docker compose ps` — состояние контейнеров.
- `sudo docker compose logs -f app` — журнал приложения.
- `sudo docker compose down` — остановка с сохранением данных.

По умолчанию Compose публикует порт приложения только на `127.0.0.1`. Порт можно изменить через `YOURTUBE_PORT`, а адрес привязки — через `YOURTUBE_BIND` в `.env`. Локальный запуск доступен по HTTP.

Для доступа из интернета настройте на том же хосте обратный прокси с TLS. Направьте запросы с публичного домена на `http://127.0.0.1:8000`, сохранив заголовок `Host`. Откройте входящий порт 443 на прокси и порт 80, если он нужен для перенаправления на HTTPS или выпуска сертификата. Оставьте порт приложения на loopback. Укажите публичный адрес в `.env` и повторно выполните `bash deploy.sh`.

```dotenv
PUBLIC_ORIGIN=https://video.example.org
```

В блоке `location` Nginx передавайте IP клиента и схему. На публичном прокси, который принимает соединения непосредственно от посетителей, заменяйте входящие заголовки значениями Nginx.

```nginx
proxy_pass http://127.0.0.1:8000;
proxy_set_header Host $host;
proxy_set_header X-Forwarded-For $remote_addr;
proxy_set_header X-Forwarded-Proto $scheme;
```

В `.env` задайте `FORWARDED_ALLOW_IPS` списком IP-адресов доверенных прокси через запятую. Указывайте адреса TCP-соединений **со стороны контейнера**, которые видны в журнале приложения при пустом списке. При подключении с хоста это может быть адрес шлюза сети Docker. Оставьте прямой доступ к порту приложения ограниченным и указывайте только адреса контролируемых прокси. После изменения выполните `bash deploy.sh`.

HTTPS в `PUBLIC_ORIGIN` автоматически включает атрибут `Secure` для cookies сессии и зрителя. Для принудительного включения предусмотрено `COOKIE_SECURE=1`. TLS завершает обратный прокси.

PostgreSQL доступен внутри сети Compose. Каталоги `postgres_data` и `video_data` хранят базу и медиа. Сохраняйте оба каталога и `.env` при переносе экземпляра. Пароль базы создаётся при первом запуске и соответствует паролю в уже инициализированной базе.

Одновременно принимаются две загрузки на весь экземпляр и одна на аккаунт. Между принятыми попытками одного аккаунта действует пауза в 60 секунд, включая попытки с повреждёнными файлами. Передача файла ограничена пятью минутами. При занятом сервере API отвечает `503`, при ограничении аккаунта — `429`. Оба ответа содержат `Retry-After`.

Для входа действует до 20 попыток на IP и до 5 на пару IP и имя аккаунта за 5 минут. При 10 неудачных входах в один аккаунт за 5 минут, суммарно по всем IP, журнал записывает событие `account_failure_spike`. Вход с другого IP остаётся доступен в пределах лимитов этого адреса и общего лимита. Для регистрации действует до 5 попыток на IP за 24 часа. Общий лимит на вход и регистрацию составляет 120 попыток в минуту. Учитываются и успешные запросы. При превышении лимита API возвращает `429` с заголовком `Retry-After`.

IP для лимитов берётся из заголовка доверенного прокси, если задан `FORWARDED_ALLOW_IPS`. При пустом списке используется IP сетевого соединения. Журнал неудачных входов, конфликтов регистрации и срабатываний лимитов доступен через `sudo docker compose logs app`. Записи содержат IP, имя аккаунта и причину отказа.

Загрузка возвращает `202 Accepted` после сохранения исходника и записи задания в PostgreSQL. Статус и прогресс доступны владельцу через `GET /api/videos/{video_id}/status`. Контейнер `worker` обрабатывает до двух роликов одновременно. После потери аренды задание можно подхватить снова. На обработку выделяется до трёх запусков, а ошибки формата сразу переводят ролик в состояние `failed`. Готовые и неудачные задания очищаются от исходников и промежуточных файлов.

`MEDIA_QUOTA_BYTES` в `.env` задаёт бюджет видеохранилища (по умолчанию 20 ГиБ). При приёме в очередь учитываются исходники, запас под результат перекодирования, незавершённое удаление и две возможные передачи. Максимальный размер итогового MP4 составляет 512 МиБ. При нехватке места API возвращает `507`. Журнал обработки доступен через `sudo docker compose logs worker`.

Интеграционные сценарии находятся в `tests/video_queue.py` и `tests/smoke.py`. Они запускаются с хоста с FFmpeg на отдельных тестовых экземплярах Compose. Укажите `YOURTUBE_TEST_PROJECT` и `YOURTUBE_TEST_URL`. Каждый сценарий регистрирует тестовые аккаунты, поэтому для независимых прогонов используйте свежие базы.

Worker принимает исходники длительностью до 60 минут, со стороной до 4096 пикселей и площадью кадра до 8 847 360 пикселей. Во время обработки он проверяет свободное место на томе и останавливает FFmpeg, если осталось меньше 256 МиБ. Docker по умолчанию выделяет Worker до двух CPU и 2 ГиБ памяти. Лимиты контейнера задаются через `WORKER_CPUS` и `WORKER_MEMORY` в `.env`.

## Первый сценарий

1. Зарегистрируйтесь и загрузите видео. После передачи файла откроется страница управления. На ней видны очередь, прогресс FFmpeg и результат обработки. По умолчанию размер исходника ограничен 512 МиБ. Лимит в байтах можно задать через `UPLOAD_MAX_BYTES` в `.env`.
2. Откройте видео в ленте или найдите его по части названия. На странице просмотра доступны лайки, комментарии, подписка и жалоба.
3. В разделе «Мои видео» откройте настройки ролика. Для приватного видео введите имя другого зарегистрированного пользователя, чтобы выдать доступ. Получатель увидит ролик в разделе «Доступные мне». Отзыв доступа закрывает последующие запросы на просмотр и обложку.
4. Создайте плейлист во вкладке своего канала. Добавляйте ролики со страницы просмотра.
5. Для первого администратора зарегистрируйте аккаунт, например `owner_admin`, и выполните команду на хосте. Подставьте имя своего аккаунта:

```bash
sudo docker compose exec db psql -U yourtube -d yourtube \
  -c "UPDATE accounts SET role='admin' WHERE handle='owner_admin';"
```

Администратор назначает модераторов в разделе «Модерация». Модератор и администратор рассматривают жалобы, скрывают и восстанавливают ролики. Роль сама по себе не даёт доступа к просмотру приватных роликов.

Установка рассчитана на один сервер с локальными томами.

## Тестовые данные

После запуска приложения выполните:

```bash
bash deploy.sh
sudo docker compose exec -T app python -m app.seed_demo
```

Миграция добавит два канала, четыре воспроизводимых ролика, плейлист, подписки, лайки, комментарии и открытую жалобу. Три видео появятся в ленте. Четвёртое доступно владельцу `demo_studio` и пользователю `demo_viewer`. Жалобу можно обработать под `demo_moderator`. Под `demo_admin` также можно назначать модераторов. Повторный запуск на базе с прежними демо-данными добавит администратора.

Пароли тестовых аккаунтов генерируются при первом запуске и выводятся один раз. Повторный запуск пропускает уже применённую миграцию. Миграция запускается вручную на выбранном экземпляре.

Для отката тестовых данных выполните:

```bash
sudo docker compose exec -T app python -m app.seed_demo down
```

Откат удаляет демо-аккаунты, их активность, тестовые ролики и связанные с ними записи, а также файлы тестовых роликов в `video_data`. Если у демо-аккаунтов есть собственные загрузки, откат отменяется целиком. Повторный `down` безопасен. Команда `up` (или запуск модуля без аргумента) создаёт демо-данные заново и выдаёт новые пароли.
